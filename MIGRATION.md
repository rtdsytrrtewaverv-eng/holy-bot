# 🔄 Как перенести бота на другой хостинг

Вся информация бота (пользователи, файлы, каналы, тексты, настройки, цвета кнопок)
хранится в **одном файле базы данных** — `bot_data.db`.
Чтобы перенести бота, достаточно перенести этот файл и переменные окружения.

> ⚠️ **Главное правило:** переносите бота с **тем же токеном** (`BOT_TOKEN`).
> `file_id` файлов в Telegram привязаны к боту. Если использовать новый токен —
> все `file_id` станут недействительны и файлы придётся добавлять заново.

---

## Что переносится

| Данные | Где хранятся |
|--------|--------------|
| Пользователи, баны | `bot_data.db` |
| Файлы, обложки, библиотека, ссылки | `bot_data.db` |
| Каналы для проверки подписки | `bot_data.db` |
| Тексты, картинки экранов | `bot_data.db` |
| Настройки и цвета кнопок | `bot_data.db` |
| Сам токен и ID админа | переменные окружения (`.env`) |

Сами большие файлы (`.ipa`, `.zip` и т.д.) **не хранятся** на хостинге — Telegram
хранит их у себя, а бот использует `file_id`. Поэтому перенос лёгкий.

---

## Способ 1. Через админку бота (проще всего)

### 1. Скачайте бэкап со старого хостинга

В боте: **👑 Админка → 💾 Бэкап → 📥 Скачать БД**.
Файл `bot_data.db` придёт в личные сообщения — сохраните его.

Либо скачайте файл напрямую с хостинга, если есть доступ к файлам:
- на bothost данные лежат в `/app/data/bot_data.db`
- локально — рядом с `bot.py`

### 2. Разверните бота на новом хостинге

Загрузите код (например, через GitHub) и задайте переменные окружения —
те же, что и раньше (см. таблицу ниже). Оставьте `BOT_TOKEN` **тем же**.

### 3. Восстановите БД

В боте на **новом** хостинге: **👑 Админка → 💾 Бэкап → 📤 Загрузить БД**
и отправьте сохранённый файл `bot_data.db`.

Готово — все файлы, тексты, каналы и настройки на месте.

> Если старый хостинг уже выключен и бот не отвечает — скачайте `bot_data.db`
> из файловой системы хостинга вручную (Способ 2).

---

## Способ 2. Напрямую через файл БД

1. **Остановите** бота на старом хостинге (чтобы не было двух экземпляров).
2. Найдите файл `bot_data.db`:
   - локально — в папке проекта;
   - bothost/Docker — `/app/data/bot_data.db` (путь задаётся `DATA_DIR`/`DB_PATH`);
   - Replit — в корне проекта.
3. Скопируйте `bot_data.db` на новый хостинг в ту же папку данных.
4. Убедитесь, что переменная `DATA_DIR` (или `DB_PATH`) указывает на папку,
   где лежит файл. Пример для bothost: `DATA_DIR=/app/data`.
5. Запустите бота.

---

## Переменные окружения

Задайте на новом хостинге те же значения:

| Переменная | Обязательно | Описание |
|-----------|:---:|----------|
| `BOT_TOKEN` | ✅ | Токен бота (от @BotFather). **Тот же**, что и раньше |
| `ADMIN_ID` | ✅ | Ваш Telegram ID (число) |
| `CHANNEL_ID` | ➖ | ID основного канала (автодобавляется при первом запуске) |
| `DATA_DIR` | ➖ | Папка для `bot_data.db` (bothost: `/app/data`) |
| `DB_PATH` | ➖ | Полный путь к файлу БД (имеет приоритет над `DATA_DIR`) |
| `PORT` | ➖ | Порт keep-alive сервера (Replit задаёт сам) |

## Чек-лист переноса

- [ ] Выключил бота на старом хостинге (нет «Conflict: terminated by other getUpdates»)
- [ ] Скачал `bot_data.db` (админка → 💾 Бэкап, либо из файловой системы)
- [ ] Загрузил код на новый хостинг
- [ ] Указал **тот же** `BOT_TOKEN`, `ADMIN_ID`, при необходимости `CHANNEL_ID`
- [ ] Восстановил БД (📤 Загрузить БД) или положил файл вручную
- [ ] Запустил бота и проверил `/start`, выдачу файла и библиотеку
- [ ] Добавил бота **администратором** в канал(ы) для проверки подписки

---

## Частые проблемы

| Проблема | Причина / решение |
|----------|-------------------|
| `Conflict: terminated by other getUpdates` | Бот запущен на двух хостингах. Выключите старый |
| Файлы не отправляются | Другой `BOT_TOKEN`. Верните прежний токен или добавьте файлы заново |
| `chat not found` | Неверный `CHANNEL_ID` или бот не добавлен в канал |
| БД пустая после переноса | Не восстановили `bot_data.db` или указали не ту папку `DATA_DIR` |
| Сборка падает с github-ошибкой | Репозиторий приватный → сделайте публичным |
